\section{Package main}

Il package \texttt{main} (Figura~\ref{fig:package_main}) contiene il
punto di ingresso del programma e coordina l’esecuzione della pipeline.
Al suo interno vengono letti i parametri del file di configurazione e
vengono avviate le principali fasi del processo.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.85\textwidth]{images/package_main.png}
    \caption{Diagramma UML del package \texttt{main}}
    \label{fig:package_main}
\end{figure}

\subsection{Classe Application}

La classe \texttt{Application}, appartenente al package \texttt{main}, è
la classe principale del programma e si occupa di leggere il file di
configurazione e, in base ai parametri
impostati, di coordinarne le diverse fasi. Per svolgere le
varie operazioni, richiama le classi responsabili della conversione dei
file PE, della creazione del file CSV con le etichette, del training e
del test del modello. Durante la fase di test, coordina anche il calcolo
delle metriche e il salvataggio dei risultati.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{peEnabled} (\texttt{bool}): indica se abilitare la fase di
    conversione PE in immagini.
    \item \textbf{filesPath} (\texttt{String}): percorso della cartella
    contenente i file PE da convertire.
    \item \textbf{labelsPath} (\texttt{String}): percorso del file CSV
    contenente i nomi dei file PE e le relative etichette.
    \item \textbf{imagesPath} (\texttt{String}): percorso della cartella in cui
    vengono salvate le immagini generate.
    \item \textbf{imageLabelsPath} (\texttt{String}): percorso del file CSV
    in cui viene salvato il mapping tra il percorso delle immagini generate e
    le relative etichette.
    \item \textbf{mappingType} (\texttt{MappingType}): strategia di mapping da
    utilizzare.
    \item \textbf{width} (\texttt{int}): larghezza delle immagini da generare.
    \item \textbf{height} (\texttt{int}): altezza delle immagini da generare.
    \item \textbf{numberOfChannels} (\texttt{int}): numero di canali
    delle immagini da generare.
    \item \textbf{resizeWidth} (\texttt{int}): larghezza per l'eventuale resize.
    \item \textbf{resizeHeight} (\texttt{int}): altezza per l'eventuale resize.
    \item \textbf{trainEnabled} (\texttt{bool}): indica se abilitare la fase di
    training del modello.
    \item \textbf{trainImageLabelsPath} (\texttt{String}): percorso del file CSV
    contenente il mapping immagini-etichette utilizzato durante il training.
    \item \textbf{epochs} (\texttt{int}): numero di epoche del training.
    \item \textbf{learningRate} (\texttt{float}): learning rate utilizzato
    durante il training.
    \item \textbf{modelPath} (\texttt{String}): percorso della cartella in cui
    viene salvato il modello addestrato.
    \item \textbf{testEnabled} (\texttt{bool}): indica se abilitare la fase di
    test del modello addestrato.
    \item \textbf{testImageLabelsPath} (\texttt{String}): percorso del file CSV
    contenente il mapping immagini-etichette utilizzato durante il test.
    \item \textbf{testModelPath} (\texttt{String}): percorso del modello addestrato
    da utilizzare durante il test.
    \item \textbf{resultsPath} (\texttt{String}): percorso del file CSV in cui
    vengono salvati i risultati del test e le metriche calcolate.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{main()} $\rightarrow$ \texttt{void}: punto di ingresso
    del programma. Coordina l’esecuzione delle diverse fasi in base ai
    parametri caricati dal file di configurazione.
    \item \textbf{parseConfig}(\texttt{configPath:String})
    $\rightarrow$ \texttt{void}: metodo
    privato che legge il file di configurazione e inizializza gli
    attributi necessari per l’esecuzione delle diverse fasi del programma.
\end{itemize}

Executable di Windows. Il suo compito principale è leggere i file PE in
formato binario e avviare il processo di conversione in immagini,
utilizzando la strategia di mapping ricevuta dalla classe \texttt{Application}.

    \caption{Diagramma UML del package \texttt{pe}}
    \label{fig:package_pe}
\end{figure}

\subsection{Classe PEFile}

La classe \texttt{PEFile}, appartenente al package \texttt{pe}, è
responsabile della conversione di un singolo file PE. Riceve il percorso
del file, il percorso della cartella in cui
salvare l’immagine e il valore di \texttt{MappingType}. Dopo aver letto il
contenuto binario del file, utilizza il valore di \texttt{MappingType}
ricevuto per individuare la strategia di mapping da applicare e salva infine
l’immagine ottenuta nella cartella specificata.

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{PEToImage}(\texttt{filePath:String},
    \texttt{imagesPath:String}, \texttt{mappingType:MappingType})
    $\rightarrow$ \texttt{void}: legge il singolo file PE indicato,
    passa la sequenza di byte al metodo \texttt{createImage} della strategia di mapping corrispondente 
    e salva l'immagine ottenuta nella cartella specificata.
\end{itemize}

\subsection{Enumerazione MappingType}

L’enumerazione \texttt{MappingType}, appartenente al package \texttt{pe},
definisce il tipo di strategia di mapping da utilizzare per la conversione
dei file PE in immagini. La classe \texttt{Application} legge il valore dal
file di configurazione e lo passa alla classe \texttt{PEFile}, che lo utilizza
per determinare la strategia di mapping da applicare durante la generazione
delle immagini.

\paragraph{Valori}

\begin{itemize}
    \raggedright
    \item \textbf{LINEAR}
    \item \textbf{ZIGZAG}
    \item \textbf{SERPENTINE}
\end{itemize}

\section{Package image\_representation}

Il package \texttt{image\_representation} contiene le funzionalità
necessarie per rappresentare i file PE sotto forma di immagini. Al suo
interno sono definite la classe \texttt{Image}, che rappresenta l’immagine
e la sua struttura, e le diverse strategie di mapping utilizzate per
disporre i byte del file nell’immagine.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/package_imagerepresentation.PNG}
    \caption{Diagramma UML del package \texttt{image\_representation}}
    \label{fig:package_image_representation}
\end{figure}

\subsection{Classe Image}

La classe \texttt{Image}, appartenente al package
\texttt{image\_representation}, rappresenta l’immagine generata
dalla conversione del file PE. L’immagine è rappresentata tramite un tensore a
tre dimensioni che contiene i valori dei pixel organizzati secondo righe,
colonne e canali. La classe riceve il tensore già costruito dalla strategia
di mapping e si occupa della sua gestione e del salvataggio su file.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{data} (\texttt{int[][][]}): tensore tridimensionale che
    contiene i valori dell’immagine organizzati in altezza, larghezza e
    numero di canali.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{Image}(\texttt{data:int[][][]}): costruttore della classe
    che inizializza l’immagine.
    \item \textbf{getWidth}() $\rightarrow$ \texttt{int}: restituisce la
    larghezza dell’immagine ricavandola dal tensore associato.
    \item \textbf{getHeight}() $\rightarrow$ \texttt{int}: restituisce
    l’altezza dell’immagine ricavandola dal tensore associato.
    \item \textbf{getNumberOfChannels}() $\rightarrow$ \texttt{int}:
    restituisce il numero di canali dell’immagine ricavandolo dal tensore
    associato.
    \item \textbf{save}(\texttt{fileName:String}) $\rightarrow$
    \texttt{void}: salva l’immagine rappresentata dal tensore associato
    nel percorso specificato. In base al numero
    di canali, l’immagine viene salvata in grayscale oppure in formato RGB.
\end{itemize}

\subsection{Classe astratta ImageMappingStrategy}

\noindent\makebox[\linewidth][l]{La classe astratta
\texttt{ImageMappingStrategy}, appartenente al package}\\
\texttt{image\_representation}, definisce il comportamento comune delle
strategie di mapping. Contiene i parametri necessari alla costruzione
dell’immagine, cioè larghezza, altezza e numero di canali, impostati prima
della fase di creazione dell’immagine. Ogni implementazione riceve in input
la sequenza di byte del file PE e costruisce l’immagine secondo la propria
strategia di mapping.
L’altezza può essere definita nel file di configurazione oppure impostata a
0 per utilizzare la modalità ad altezza variabile. In questo caso, l’altezza
necessaria viene calcolata durante la creazione dell’immagine senza
modificare la configurazione della strategia.
La gestione dei canali permette di costruire immagini sia in grayscale
(1 canale) sia RGB (3 canali), modificando il modo in cui i byte vengono
letti e inseriti nel tensore, in particolare un byte per pixel nel caso
grayscale oppure gruppi di tre byte per pixel nel caso RGB.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{width} (\texttt{int}): attributo di classe che rappresenta
    la larghezza comune utilizzata per la costruzione delle immagini.
    \item \textbf{height} (\texttt{int}): attributo di classe che rappresenta
    l’altezza comune utilizzata per la costruzione delle immagini.
    \item \textbf{numberOfChannels} (\texttt{int}): attributo di classe che
    rappresenta il numero di canali utilizzato per definire la struttura
    del tensore.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{setImageSize}(\texttt{width:int}, \texttt{height:int},
    \texttt{numberOfChannels:int}) $\rightarrow$ \texttt{void}: metodo
    di classe che imposta i parametri comuni utilizzati dalle strategie per
    costruire l’immagine.
    \item \textbf{getVariableHeight}(\texttt{byteCount:int})
    $\rightarrow$ \texttt{int}: metodo di classe che calcola e restituisce
    l’altezza necessaria in base al numero di byte da rappresentare, quando
    l’altezza non è definita.
    \item \textbf{getWidth}() $\rightarrow$ \texttt{int}: metodo di classe
    che restituisce la larghezza configurata.
    \item \textbf{getHeight}() $\rightarrow$ \texttt{int}: metodo di classe
    che restituisce l’altezza configurata.
    \item \textbf{getNumberOfChannels}() $\rightarrow$ \texttt{int}: metodo 
    di classe che restituisce il numero di canali configurato.
    \item \textbf{createImage}(\texttt{byteData:byte[]}) $\rightarrow$
    \texttt{Image}: metodo astratto che viene implementato dalle classi
    derivate in base alla strategia di mapping utilizzata e che costruisce
    e restituisce un oggetto della classe \texttt{Image} a partire dalla
    sequenza di byte del file PE.
\end{itemize}

\subsection{Classe LinearMapping}

La classe \texttt{LinearMapping}, appartenente al package
\texttt{image\_representation}, eredita dalla classe astratta
\texttt{ImageMappingStrategy} e implementa il mapping disponendo i byte nel
tensore in modo sequenziale, da sinistra verso destra e dall’alto
verso il basso.

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{createImage}(\texttt{byteData:byte[]}) $\rightarrow$
    \texttt{Image}: implementa il metodo astratto della classe
    \texttt{ImageMappingStrategy} e costruisce l’immagine utilizzando il
    mapping Linear.
\end{itemize}

\subsection{Classe ZigZagMapping}

La classe \texttt{ZigZagMapping}, appartenente al package
\texttt{image\_representation}, eredita dalla classe astratta
\texttt{ImageMappingStrategy} e implementa il mapping disponendo i byte
nel tensore in modo sequenziale e alternando il verso di percorrenza delle
righe.

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{createImage}(\texttt{byteData:byte[]}) $\rightarrow$
    \texttt{Image}: implementa il metodo astratto della classe
    \texttt{ImageMappingStrategy} e costruisce l’immagine utilizzando il
    mapping Zigzag.
\end{itemize}

\subsection{Classe SerpentineMapping}

La classe \texttt{SerpentineMapping}, appartenente al package
\texttt{image\_representation}, eredita dalla classe astratta
\texttt{ImageMappingStrategy} e implementa il mapping disponendo i byte
nel tensore lungo le diagonali e alternando la direzione di percorrenza.

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{createImage}(\texttt{byteData:byte[]}) $\rightarrow$
    \texttt{Image}: implementa il metodo astratto della classe
    \texttt{ImageMappingStrategy} e costruisce l’immagine utilizzando il
    mapping Serpentine.
\end{itemize}

\section{Package dataloader}

Il package \texttt{dataloader} si occupa di preparare le immagini e le
relative etichette per essere utilizzate dal modello. Gestisce la
creazione dei dataset e dei dati necessari per il training, la validation
e il test.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/package_dataloader.PNG}
    \caption{Diagramma UML del package \texttt{dataloader}}
    \label{fig:package_dataloader}
\end{figure}

\subsection{Classe ImageDataset}

La classe \texttt{ImageDataset}, appartenente al package
\texttt{dataloader}, rappresenta il dataset, eredita da
\texttt{torch.utils.data.Dataset} e si occupa della gestione delle immagini
generate dalla conversione dei file PE e delle relative etichette contenute
nel file CSV. Il suo compito è fornire le coppie immagine-etichetta richieste
dal \texttt{DataLoader} e, se necessario, applicare il resize delle immagini
e la normalizzazione prevista per il modello ResNet.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{images} (\texttt{String[]}): array contenente i percorsi
    completi delle immagini letti dal file CSV.
    \item \textbf{labels} (\texttt{Tensor}): tensore PyTorch contenente le
    etichette associate alle immagini.
    \item \textbf{needResize} (\texttt{bool}): indica se deve essere
    applicato il resize alle immagini.
    \item \textbf{resizeWidth} (\texttt{int}): larghezza per l'eventuale
    resize.
    \item \textbf{resizeHeight} (\texttt{int}): altezza per l'eventuale
    resize.
    \item \textbf{upsample} (\texttt{nn.Upsample}): modulo utilizzato
    per ridimensionare le immagini quando il resize è abilitato.
    \item \textbf{normalize} (\texttt{Normalize}): trasformazione
    utilizzata per normalizzare i valori dei pixel prima di passarli al
    modello.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{ImageDataset}(\texttt{imageLabelsPath:String},
    \texttt{needResize:bool}, \texttt{resizeWidth:int},
    \texttt{resizeHeight:int}): costruttore della classe che legge il file
    CSV, estrae i percorsi delle immagini e le etichette e inizializza i
    parametri necessari per il caricamento, la normalizzazione e l’eventuale resize delle immagini.
    \item \textbf{len}() $\rightarrow$ \texttt{int}: restituisce
    il numero totale di elementi presenti nel dataset.
    \item \textbf{getitem}(\texttt{index:int})
    $\rightarrow$ \texttt{(Tensor, Tensor)}: recupera l’immagine e
    l’etichetta corrispondente all’indice indicato. L’immagine viene
    convertita in un tensore, normalizzata ed eventualmente ridimensionata.
\end{itemize}

\subsection{Classe DataLoader}

La classe \texttt{DataLoader}, appartenente al package
\texttt{dataloader}, prepara i dati che vengono utilizzati dal modello
durante le fasi di training, validation e test. A partire dal percorso del
file CSV e dai parametri relativi al resize, crea un oggetto della classe
\texttt{ImageDataset} e lo utilizza per costruire i \texttt{DataLoader} di
PyTorch.
Durante il training, il dataset viene diviso in due parti, una utilizzata
per il training e una per la validation. Durante il test, invece, viene
utilizzato un unico dataset contenente le immagini da classificare.

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{buildTrainValidationLoader}
    (\texttt{imageLabelsPath:String}, \texttt{needResize:bool},
    \texttt{resizeWidth:int}, \texttt{resizeHeight:int})
    $\rightarrow$ \texttt{(torch.utils.data.DataLoader,
    torch.utils.data.DataLoader)}: crea il dataset, lo
    divide in training e validation e restituisce due oggetti
    \texttt{torch.utils.data.DataLoader}: \texttt{trainLoader} e
    \texttt{validationLoader}.
    \item \textbf{buildTestLoader}(\texttt{imageLabelsPath:String},
    \texttt{needResize:bool}, \texttt{resizeWidth:int},
    \texttt{resizeHeight:int}) $\rightarrow$
    \texttt{torch.utils.data.DataLoader}: crea il dataset di test e
    restituisce un oggetto \texttt{torch.utils.data.DataLoader},
    denominato \texttt{testLoader}.
\end{itemize}

Il package \texttt{model} contiene le funzionalità relative al modello di
classificazione. Si occupa dell’addestramento, della validazione e del
test della rete neurale utilizzata per distinguere i file goodware dai
file malware.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{images/package_model.PNG}
    \caption{Diagramma UML del package \texttt{model}}
    \label{fig:package_model}

\subsection{Classe ResNetModel}

La classe \texttt{ResNetModel}, appartenente al package \texttt{model}, è
responsabile della gestione del modello di classificazione basato su una
ResNet-50 preaddestrata. Si occupa dell’inizializzazione del modello,
dell’addestramento, della validazione e del
test. Durante il training salva il modello che ottiene la validation loss più
bassa, mentre durante il test restituisce la matrice di confusione
ottenuta confrontando le etichette reali con quelle predette.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{device} (\texttt{torch.device}): dispositivo utilizzato
    per eseguire il modello (CPU o GPU).
    \item \textbf{model} (\texttt{ResNetForImageClassification}): modello
    ResNet-50 utilizzato per la classificazione delle immagini.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{ResNetModel}(\texttt{modelPath:String}): costruttore
    della classe. Se il percorso del modello non viene specificato,
    inizializza una ResNet-50 preaddestrata, altrimenti carica un modello
    precedentemente salvato.
    \item \textbf{train}(\texttt{trainLoader:DataLoader},
    \texttt{validationLoader:DataLoader}, \texttt{epochs:int},
    \texttt{learningRate:float}, \texttt{modelPath:String})
    $\rightarrow$ \texttt{void}: esegue il training del modello, calcola la
    training loss e la validation loss a ogni epoca e salva automaticamente
    il modello che ottiene la validation loss più bassa.
    \item \textbf{validate}(\texttt{validationLoader:DataLoader},
    \texttt{criterion:CrossEntropyLoss}) $\rightarrow$ \texttt{float}:
    metodo privato che esegue la fase di validazione e restituisce la
    validation loss media.
    \item \textbf{test}(\texttt{testLoader:DataLoader})
    $\rightarrow$ \texttt{ndarray}: esegue il test del modello e restituisce
    la matrice di confusione ottenuta confrontando le etichette reali con
    quelle predette.
\end{itemize}

tra i percorsi delle immagini e le relative etichette e il calcolo delle
metriche a partire dalla matrice di confusione ottenuta durante la
classificazione.

\begin{figure}[H]

    \caption{Diagramma UML del package \texttt{utils}}
    \label{fig:package_utils}

\subsection{Classe LabelDictionary}

La classe \texttt{LabelDictionary}, appartenente al package \texttt{utils},
è responsabile della gestione delle etichette dei file PE e del mapping tra
le immagini generate e le relative etichette. Contiene due dizionari
privati: il primo associa il nome del file PE alla relativa etichetta,
mentre il secondo associa il percorso dell’immagine generata alla relativa
etichetta. Inizializza il primo dizionario nel costruttore, leggendo le etichette presenti nel
file CSV ricevuto, e costruisce durante la conversione il mapping nel secondo dizionario, che
successivamente viene salvato in un file CSV nel percorso specificato.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{labelDictionary}
    (\texttt{Dictionary<String, Integer>}): dizionario privato che associa
    il nome del file PE alla relativa etichetta.
    \item \textbf{imageLabelDictionary}
    (\texttt{Dictionary<String, Integer>}): dizionario privato che associa
    il percorso dell’immagine alla relativa etichetta.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{LabelDictionary}(\texttt{labelsPath:String}): legge il
    file CSV delle etichette e inizializza il primo dizionario.
    \item \textbf{addLabelImage}(\texttt{fileName:String},
    \texttt{imagePath:String}) $\rightarrow$ \texttt{void}: recupera
    l’etichetta del file PE e aggiunge il mapping tra immagine ed etichetta
    al secondo dizionario.
    \item \textbf{save}(\texttt{imageLabelsPath:String})
    $\rightarrow$ \texttt{void}: salva il secondo dizionario in un file CSV.
\end{itemize}

\subsection{Classe ClassificationMetrics}

La classe \texttt{ClassificationMetrics}, appartenente al package
\texttt{utils}, è responsabile del calcolo e del salvataggio delle metriche
di classificazione. Riceve la matrice di confusione restituita dal test del
modello ed estrae i quattro valori TN, FP, FN e TP. A partire da questi
valori calcola l’overall accuracy e, per le classi goodware e malware, la
precision, il recall e l’F1-score. Salva inoltre i risultati della
configurazione in un file CSV.

\paragraph{Attributi}

\begin{itemize}
    \raggedright
    \item \textbf{trueNegative} (\texttt{int}): numero di campioni
    goodware classificati correttamente.
    \item \textbf{falsePositive} (\texttt{int}): numero di campioni
    goodware classificati come malware.
    \item \textbf{falseNegative} (\texttt{int}): numero di campioni
    malware classificati come goodware.
    \item \textbf{truePositive} (\texttt{int}): numero di campioni
    malware classificati correttamente.
    \item \textbf{precisionGoodware} (\texttt{float}): precision calcolata
    per la classe goodware.
    \item \textbf{recallGoodware} (\texttt{float}): recall calcolata per
    la classe goodware.
    \item \textbf{f1Goodware} (\texttt{float}): F1-score calcolato per la
    classe goodware.
    \item \textbf{precisionMalware} (\texttt{float}): precision calcolata
    per la classe malware.
    \item \textbf{recallMalware} (\texttt{float}): recall calcolata per la
    classe malware.
    \item \textbf{f1Malware} (\texttt{float}): F1-score calcolato per la
    classe malware.
    \item \textbf{overallAccuracy} (\texttt{float}): overall accuracy
    calcolata.
\end{itemize}

\paragraph{Metodi}

\begin{itemize}
    \raggedright
    \item \textbf{ClassificationMetrics}(\texttt{confusionMatrix:ndarray}):
    costruttore della classe. Riceve la matrice di confusione ed estrae i
    valori TN, FP, FN e TP.
    \item \textbf{calculateMetrics}() $\rightarrow$ \texttt{void}: calcola
    l’overall accuracy e, per le classi goodware e malware, la precision,
    il recall e l’F1-score.
    \item \textbf{save}(\texttt{resultsPath:String},
    \texttt{configuration:Dictionary}) $\rightarrow$ \texttt{void}: salva
    i valori della matrice di confusione e le metriche calcolate insieme
    alla configurazione del modello testato in una riga del file CSV dei
    risultati.
\end{itemize}
